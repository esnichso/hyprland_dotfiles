# CLAUDE.md

Notes for future sessions working in this repo. Read this before touching
anything — most of it was learned the hard way, in a session where each
mistake cost a broken desktop.

## What this is

A hand-written Hyprland desktop for **CachyOS** on a **ThinkPad E16 Gen 3**.
Not a fork of anyone's dotfiles: every line is written for this machine and
commented so it can be maintained rather than copied.

Hardware facts that the config depends on:

| | |
| --- | --- |
| CPU | Intel Core Ultra 7 255H (Arrow Lake-H) — **no AVX-512**, so CachyOS **v3** repos, never v4 |
| GPU | Intel Arc iGPU — no NVIDIA workarounds needed anywhere |
| Display | single `eDP-1`, **2560×1600**, scale **1.6** (1.5 is invalid: 2560/1.5 isn't a whole number) |
| Keyboard | German (`de`), **no Print key** — screenshots live on `SUPER+SHIFT+S/D/A` |
| Battery | `BAT0` + `AC` — absent in the VM, so the bar's battery module only appears on metal |

## Where things live

| Machine | Path |

| Test VM / ThinkPad | `~/hyprland_dotfiles` |
| Remote | `github.com/esnichso/hyprland_dotfiles` (SSH, key already on the account) |

`install/link.sh` symlinks each entry of `config/` into `~/.config`, moving
anything already there into `~/.config-backup-<timestamp>/`. **Re-run it after
any pull that adds a new config directory** — a plain `git pull` leaves new
directories unlinked, and the symptom is "my change did nothing".

## Workflow

The host runs Ubuntu/GNOME. **You cannot test any of this locally.** Hyprland,
Waybar, rofi and hyprlock are not installed here and will not run. Everything
is verified either statically (see below) or by the user in the VM.

```
edit here  →  ./install/check.sh  →  commit  →  push  →  user pulls in the VM
```

- **Always run `./install/check.sh` before committing.** It has caught real
  bugs every single time it was extended.
- One commit per concern. Explain *why* in the body, not what — the diff shows
  what. Past commit messages are a good model.
- The user pulls and reports back, often with screenshots. Screenshots of a
  *symptom* are ambiguous; ask for `waybar` / `hyprlock --verbose` / `rofi`
  stderr when the cause isn't obvious from the config.

### What check.sh validates

Lua (`luac` when present), JSONC, **GTK CSS via GTK's own parser**, TOML, shell
syntax, rofi themes (`install/check-rofi.py`), duplicate keybinds, and whether
the generated colour files still match the theme.

Two notes on the CSS check: it uses `load_from_path`, **not** `load_from_data`,
because `@import` must resolve relative to the file the way Waybar resolves it.
And it needs `python-gobject`; it skips silently if that's missing, so don't
assume green means checked on a fresh machine.

## Colours are generated — do not edit them

`themes/*.toml` is the **only** place a colour is written.
`install/set-theme.py` renders 13 files from it.

```bash
./install/set-theme.py            # list
./install/set-theme.py mocha      # apply
./install/set-theme.py --pick     # rofi picker (SUPER+ALT+T does this + reloads)
./install/set-theme.py mocha --check   # used by check.sh to detect drift
```

Two mechanisms, chosen per format:

- **Generated file + import** where the format supports one: CSS `@import`,
  kitty `include`, rofi `@import`, fish `source`, hyprlang `source`. The
  hand-written config stays hand-written.
- **Marked region** (`>>> palette >>>` … `<<< palette <<<`) where no import
  exists: `starship.toml`, `waybar/config.jsonc`, `gtk-3.0/settings.ini`.

Configs reference **roles** (`@accent`, `@urgent`, `@warning`), not palette
names, so re-pointing `accent` in the theme restyles everything coherently.
Files with a "Generated by install/set-theme.py" header are overwritten on the
next run — edit the theme instead.

## Hard-won gotchas

**Hyprland 0.55+ is Lua-only.** hyprlang configs are dead. Essentially every
tutorial, video and dotfile repo older than May 2026 is written in a syntax
this version cannot read. `docs/hyprland/` is a local snapshot of the upstream
wiki (fetch from `raw.githubusercontent.com/hyprwm/hyprland-wiki/main/content/…`
— the rendered site is JavaScript and unfetchable). **Check syntax there before
writing it.**

**But the other hypr\* tools are still hyprlang** — `hyprlock.conf`,
`hypridle.conf`, `hyprpaper.conf`. Don't convert them to Lua.

**Docs tables use path notation, not file syntax.** The hyprlock wiki lists
`pam:enabled`; in the file that's a nested block. Writing it flat defines an
option that doesn't exist, hyprlock exits, and the session is left locked with
no lock screen — recoverable only from a TTY. Same class of error as assuming
`hyprshutdown` was a menu because of its name: it's a graceful-exit tool, and
binding it logs you straight out.

**rofi's rasi parser has three traps**, all enforced now by `check-rofi.py`:
1. A comment **inside** a `{ }` block silently discards every declaration after
   it. The symptom is "variable 'x' failed to resolve" for exactly the names
   that followed it.
2. A theme with no `* { }` block gets rofi's built-in **light** defaults for
   any widget it doesn't style — a white dialog on a dark desktop, with every
   variable resolving fine.
3. Undefined `@variables` fail quietly.

**GTK CSS is not web CSS.** `:empty` is valid CSS and unimplemented in GTK, and
one unknown pseudo-class makes GTK reject the *entire* stylesheet — the bar
comes up completely unstyled. Validate with GTK's parser, never by eye.

**swaync's `config.json` is strict JSON.** A single `//` comment stops the
daemon starting. Explanations go in `config/swaync/NOTES.md`.

**Transparency has two independent layers.** A Hyprland window-rule `opacity`
fades text along with the background; the terminal's own `background_opacity`
fades only the background. And `decoration.blur.xray = true` makes floating
windows composite against the *wallpaper* instead of the window behind them —
a floating terminal over a browser then looks completely opaque. It is off for
that reason; don't re-enable it for performance without understanding the cost.

**`autostart.lua` fires on `hyprland.start` only.** `hyprctl reload` re-reads
config but does not re-run autostart, so anything newly added there won't run
until the next login. Say so rather than letting the user think it's broken.

**`git pull` races with Hyprland's auto-reload.** Hyprland reloads the instant
a file changes; git rewrites files one at a time, so a reload can land while a
file is momentarily missing. `hyprland.lua` wraps each `require` in `pcall` for
this — `require`'s built-in error isolation does *not* cover module lookup, and
without the guard a missing file drops the session into emergency mode with no
binds at all.

**hyprpaper rotates by default.** With a directory as `path` it cycles on
`timeout`, default 30 seconds. The user explicitly does not want automatic
changes: `hyprpaper.conf` declares no wallpaper at all, and
`scripts/wallpaper.sh` drives it over IPC, storing the choice in
`~/.local/state/hypr/wallpaper`. Never write the selection back into
`hyprpaper.conf` — it's a symlink into this repo and would leave the tree
permanently dirty.

**Verify package names against live APIs**, not memory. Real corrections found
this way: `rofi-wayland` no longer exists (merged into `rofi` 2.0),
`hyprland-qtutils` → `hyprland-guiutils`, `ttf-font-awesome` → `otf-font-awesome`,
`nwg-displays` writes dead hyprlang syntax. Also check what an AUR package
*drags in*: `bibata-cursor-theme` builds cursors with `python-clickgen`, pulling
Pillow, numpy and BLAS — about 20 permanent packages for a cursor theme.
`-bin` variants are often the right call.

## Verify your own work

The most embarrassing bug in this repo's history: an edit script whose regex
was `^`-anchored without `re.M`, so it matched nothing on a file starting with
a comment — and printed "rewrote launcher.rasi" regardless. That wrong claim
was then reported to the user as fact, and cost a round trip to discover.

Check the file, not the script's own success message.

## User preferences

- **Flag guesses explicitly.** When something is inferred rather than verified,
  say so and say how to test it. This has been valued repeatedly.
- Wants to understand *why*, not just receive a fix. Explain the mechanism.
- No automatic wallpaper changes.
- Colour as signal, not decoration — the bar is neutral at rest and only
  colours things that need attention.
- Prefers official repos over AUR where there's a choice.
- Corrections should be plain and brief. No over-apologising, no re-litigating.
